# ליבנה 6 - מערכת ניהול ושקיפות בניין

Next.js 14 + Supabase + Tailwind, RTL מלא בעברית.

## מה כבר בנוי (שלב 1)

- התחברות עם Magic Link (מייל, ללא סיסמה)
- Dashboard: יתרת קופה, הכנסות/הוצאות החודש, מצב גביית ועד
- דיירים לפי קומה ומספר דירה, כולל סימון שכירות ושם בעל הדירה
- כספי הבניין (רשימת תנועות הכנסה/הוצאה)
- בקשות ותקלות
- תוכניות לעתיד (פרויקטים) עם סטטוס
- הודעות ועד הבית
- מסד הנתונים המלא כבר קיים ב-Supabase, כולל כל 22 הישויות מהמפרט (תשלומים, ספקים, מסמכים, הצבעות, Audit Log וכו') - גם אם עדיין אין להן מסך

## מה עוד לא נבנה (שלב 2, בהמשך)

- מסכי ניהול למנהל (הוספת הוצאה/הכנסה, סימון תשלום, ניהול דיירים, פרסום הודעה, פתיחת פרויקט, יצירת הצבעה)
- מסך תשלומי ועד לפי חודש עם סיכום גבייה
- מסמכים, ספקים, הצבעות (תצוגה)
- דוחות + ייצוא PDF/Excel
- Audit Log - תצוגה
- חיפוש וסינון, התראות
- OCR לקבלות

## הרצה מקומית

```bash
npm install
cp .env.local.example .env.local
npm run dev
```

## פריסה (מומלץ Vercel)

1. להעלות את התיקייה הזו לריפו ב-GitHub.
2. לייבא את הריפו ל-Vercel.
3. להגדיר משתני סביבה בפרויקט ב-Vercel (מתוך `.env.local.example`):
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. Deploy.

## הפיכת המשתמש הראשון למנהל (ועד בית)

מסד הנתונים כבר מוכן ומאוכלס בנתוני דוגמה של בניין "ליבנה 6" (19 דירות, 7 קומות).
כדי להתחבר בפועל:

1. היכנס/י לאפליקציה עם המייל שלך (Magic Link) - זה ייצור משתמש ב-Supabase Auth אך **עדיין בלי הרשאות**, כי טבלת `app_users` מקשרת בין המשתמש לבניין ולתפקיד.
2. בלוח הבקרה של Supabase (SQL editor), הרץ:

```sql
insert into app_users (auth_id, building_id, role)
values (
  '<ה-auth user id שלך, מ-Authentication > Users>',
  (select id from buildings where name = 'ליבנה 6'),
  'admin'
);
```

3. לדיירים אחרים - אותו דבר, עם `role = 'resident'` ו-`resident_id` שמצביע לרשומה המתאימה בטבלת `residents` (כדי לקשר אותם לדירה הנכונה).

בהמשך אפשר לבנות מסך הזמנת דיירים כדי שזה לא יהיה ידני.
